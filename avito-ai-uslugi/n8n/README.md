# Avito — автоответы по услугам ИИ-автоматизации (n8n + Claude API)

Импортируемый воркфлоу `avito-autoreply-uslugi.json`. Запускается на
self-hosted n8n (Вариант Б из брифа — без подписок на SaaS-автоматизацию).

## Что делает воркфлоу

**Основной поток (вебхук):**
1. Принимает входящее сообщение Avito, проверяет подпись
   `x-avito-messenger-signature` (HMAC-SHA256 от тела запроса с секретом
   `AVITO_WEBHOOK_SECRET` — тот же алгоритм, что в
   [`src/avito_uslugi/webhooks.py`](../src/avito_uslugi/webhooks.py);
   если у владельца уже есть подтверждённый реальный алгоритм — поменять
   только узел «Code: проверка подписи HMAC»).
2. Отбрасывает вебхуки на собственные исходящие сообщения (сравнение
   `author_id` с `AVITO_USER_ID`), чтобы бот не отвечал сам себе.
3. Получает токен Avito (`client_credentials`), подтягивает контекст —
   карточку объявления (`items:info`) и историю чата (`messenger:read`).
4. Отправляет контекст в Claude (`claude-sonnet-4-6`, Messages API) с
   системным промптом из агента `client-comms` (тон практика, мягкая
   квалификация задачи, без выдуманных цен/сроков). Модель возвращает
   `{reply, escalate, reason}` строго в JSON.
5. Если `escalate=false` — отправляет `reply` клиенту напрямую
   (`messenger:write`).
   Если `escalate=true` — клиенту уходит мягкое «передал владельцу,
   вернётся с оценкой», а владельцу в Telegram — текст клиента, причина
   эскалации и ссылка на чат.

**Фоновый поток (расписание, раз в `FOLLOWUP_HOURS_THRESHOLD`/2 часа):**
6. Проверяет чаты, где последнее сообщение — наше, а клиент молчит дольше
   `FOLLOWUP_HOURS_THRESHOLD` часов (по умолчанию 20), и шлёт одно
   вежливое напоминание без давления. Чтобы не дублировать, отправленные
   напоминания помечаются в static data воркфлоу — «не более одного
   напоминания на чат».

## Удешевление классификации escalate (опционально)

Промпт допускает вынести классификацию `escalate` в отдельный, более
дешёвый вызов `claude-haiku-4-5-20251001`: добавить узел HTTP-запроса по
аналогии с «HTTP: Claude — ответ и escalate», но с укороченным системным
промптом только под бинарную классификацию (эскалировать/нет + причина),
а полноценный текст ответа продолжает генерировать sonnet. В этой версии
для простоты обе задачи решает один вызов sonnet — разделение можно
сделать по мере роста объёма переписки и расходов на API.

## Credentials, которые нужно настроить в n8n

Все секреты — только из переменных окружения n8n (`.env` инстанса
n8n или Settings → Variables), **не** хранить в самом воркфлоу:

| Переменная | Где взять | Зачем |
|---|---|---|
| `AVITO_CLIENT_ID`, `AVITO_CLIENT_SECRET` | Кабинет Avito → Настройки → API (platform.avito.ru) | OAuth2 `client_credentials`, получение токена для items/messenger |
| `AVITO_WEBHOOK_SECRET` | Задаётся при подписке вебхука (см. ниже) | Проверка подписи входящих вебхуков |
| `AVITO_USER_ID` | Кабинет Avito → профиль (числовой id аккаунта) | Отличить свои сообщения от клиентских, идентифицировать чаты в follow-up |
| `ANTHROPIC_API_KEY` | console.anthropic.com → API Keys | Вызовы Claude Messages API |
| `TELEGRAM_BOT_TOKEN` | @BotFather → создать бота → токен | Уведомления владельцу при эскалации |
| `TELEGRAM_OWNER_CHAT_ID` | @userinfobot или похожий — узнать свой chat_id | Кому именно слать уведомления |
| `FOLLOWUP_HOURS_THRESHOLD` | Своё значение (по умолчанию `20`) | Порог молчания для follow-up-напоминания |

## Какую вебхук-подписку настроить в кабинете Avito

1. Убедиться, что подключён **платный тариф** с доступом к Avito
   Messenger API (без него `messenger:read`/`messenger:write` и подписка
   на вебхуки недоступны — это явно указано в брифе).
2. В кабинете разработчика (platform.avito.ru) выпустить
   `AVITO_CLIENT_ID`/`AVITO_CLIENT_SECRET` со scope:
   `messenger:read`, `messenger:write`, `items:info`
   (последний — чтобы воркфлоу мог подтягивать карточку объявления для
   контекста ответа).
3. Активировать воркфлоу в n8n и скопировать **Production URL** узла
   «Webhook: сообщение Avito» (после импорта путь — `/avito-messenger-uslugi`,
   можно переименовать на своё).
4. Подписаться на уведомления о новых сообщениях — вызовом
   `POST /messenger/v3/webhook` (см. `MessengerAPI.subscribe_webhook_v3`
   в обёртке проекта) с этим URL и секретом, который затем кладётся в
   `AVITO_WEBHOOK_SECRET`. Проверить активные подписки можно через
   `GET /messenger/v1/subscriptions` (`MessengerAPI.subscriptions`).
5. Сделать тестовое сообщение в свой же чат и проверить в логах n8n,
   что: подпись прошла проверку → подтянулся контекст → пришёл ответ
   Claude → клиент получил сообщение (или владелец — уведомление в
   Telegram, если сценарий escalate).

## Что проверить вручную перед включением в проде

- [ ] Реальный алгоритм `x-avito-messenger-signature` — в документации
      Avito не описан официально; используемый здесь HMAC-SHA256 — это
      best-guess по длине подписи (64 hex-символа) и отраслевой
      конвенции (как `x-hub-signature-256`). Свериться по факту первых
      входящих вебхуков.
- [ ] Кеширование токена Avito — сейчас воркфлоу получает новый токен на
      каждое сообщение; для продакшена разумно кешировать (Redis/static
      data n8n) с учётом времени жизни (`expires_in`), как это сделано в
      `TokenCache` обёртки проекта.
- [ ] Лимиты и стоимость вызовов Claude — отслеживать объём, при росте
      нагрузки рассмотреть вынос классификации `escalate` на haiku
      (см. раздел выше).
- [ ] Тексты системного промпта — синхронизировать с правилами агента
      `client-comms` (`~/.claude/agents/client-comms.md`), если они
      изменятся, обновить узел «HTTP: Claude — ответ и escalate».
